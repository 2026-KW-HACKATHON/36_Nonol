# 공유 팀 방 정책과 게임 기획

Test Lab에서 사용하는 팀 대기실 정책과 상태 로직, 확정 서비스 흐름 및 게임 기획을 관리한다. 이 공개 범위는 운영 게임 UI와 Worker를 포함하지 않는다. 실행 코드는 [game-lab/](../game-lab/)에 있다.

## 핵심 파일

| 경로 | 역할 |
| --- | --- |
| [public/room-policy.json](public/room-policy.json) | 입장, 준비 완료, 첫 입장자 팀장, 팀장 양도와 공동 시작의 정책 원본 |
| [src/room-state.js](src/room-state.js) | 공유 팀 방 상태와 권한 검사 |
| [scripts/render-policy.mjs](scripts/render-policy.mjs) | 방 정책 원본에서 대기실 SSOT 문서를 생성 |
| [docs/](docs/) | 서비스 흐름, Test Lab, 고정 코스, 정령과 공간 AR 정책 및 개발과 검증 안내 |

## 확정 묵언수행 흐름

원본은 [서비스 흐름 SSOT](docs/261009_0313_서비스흐름_정책_SSOT.md)다. 아래 흐름은 구현할 사용자 경험이며 운영 연결 완료를 뜻하지 않는다.

| 순서 | 참가자 경험 | 다음 화면이 열리는 기준 |
| --- | --- | --- |
| 신청과 당일 안내 | 기존 그룹 2명 이상이 날짜와 시간을 정해 신청하고 당일 카카오톡 안내 링크를 받는다. 외부 Chrome 사용 안내를 확인한다 | 전달받은 링크로 방 입장 |
| 팀 입장 | 첫 입장자가 팀장이 된다. 혼자 입장했다면 나머지 신청 구성원의 참여를 장려한다 | 각자 준비와 노놀판 확인 |
| 이층집 식사와 출발 | 식사를 마친 뒤 전원이 노놀판을 태그한다 | 전원 준비 및 태그 후 팀장 시작 |
| 우이천 초입으로 이동 | 2D 지도에서 자신과 팀원의 위치 및 이번 목적지를 확인한다 | 전원 초입 도착 확인 후 사진 화면 |
| 초입 사진 인증 | 제시 물체를 촬영하고 묵언 규칙을 확인한다 | 사진 성공 및 안내 확인. 인증 인원과 확인 방식은 운영 정책 확정 대기 |
| 우이천 묵언 산책 | AR 길을 따라 걷고 말한 팀원을 신고한다 | 전원 정령 지점 도착 확인 후 만남 화면 |
| 솥고집 정령 | AR 정령을 터치하고 카페 추천 이야기를 본다 | 상호작용과 이야기 완료. 개인 및 팀 집계는 운영 정책 확정 대기 |
| 카페 탐색 | 지도 없이 거리, 방향과 색을 단서로 이동한다 | 전원 카페 도착 확인 후 주문 화면 |
| 카페 마무리 | 커피 주문 후 전원이 노놀판을 태그한다 | 전원 마무리 확인 후 완주와 벌점 엔딩 |

가격은 8,000원이며 1인 또는 그룹 적용 단위는 확인 대기다. 방 미입장 또는 다른 브라우저에서 입장 정보를 복원하지 못한 참가자에게는 카카오톡 안내 링크로 입장하도록 안내하는 흐름을 정의한다. 실제 신청 DB와 방 연결, 카카오톡 자동 발송, 미입장 안내의 복귀 및 카페 주문과 NFC 연결은 후속 개발이다.

## Test Lab과의 관계

[Test Lab](https://nonol-game-lab.1991knet.workers.dev)에서는 한 명부터 준비 후 시작하고 독립 모듈을 시험한다. [/tracks](https://nonol-game-lab.1991knet.workers.dev/tracks)에서는 관리자가 등록한 학교 네 장소와 에어팟 원본으로 모듈 연결을 시험한다. 복지관이 이층집, 광운스퀘어가 우이천 초입, 광운스퀘어에서 비마관 앞까지가 우이천, 비마관 앞이 정령 지점, 풋살장이 카페 역할이다.

운영 서비스 정책과 Test Lab의 시험 설정은 각각의 원본을 따른다. 공유 방 정책은 public/room-policy.json, 모듈 시험 정책은 [game-lab/public/test-track.json](../game-lab/public/test-track.json), 고정 코스 정의는 [game-lab/public/261009_0536_campus-track.json](../game-lab/public/261009_0536_campus-track.json)에서 관리한다.

개발과 현장 QA는 [개발 순서](docs/261008_1318_개발모듈과_작업순서.md)와 [검증 안내](docs/261008_1541_테스트모듈과_검증.md)를 따른다. 실행 방법은 [Test Lab 안내](../game-lab/README.md), 공개 완료 기록과 현장 한계는 [Test Lab 작업 기록](../game-lab/WORKLOG.md)에 있다.
