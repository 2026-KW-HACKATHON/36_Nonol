# 테스트 모듈과 검증

갱신 시각: 2026-10-09 06:37:19 KST
기준: nonol-test-lab-v15 및 캠퍼스 고정 트랙 정의 v2.
상태: 운영 적용 전에 독립 모듈과 연결 코스를 반복 시험한다.

테스트 주소는 https://nonol-game-lab.1991knet.workers.dev 이다. 운영 제품과 별도 Worker 및 방 저장소를 사용한다. 시험 전에 전원이 새로고침해 최신 화면을 받는다.

## 공통 입장과 준비

1. 같은 방 링크를 각자 휴대폰에서 열고 닉네임으로 입장한다. 첫 입장자가 팀장이다.
2. 팀장을 포함한 전원이 준비 완료를 누른 뒤 팀장이 시작한다. 혼자도 준비 후 시작하며 인원 상한은 없다.
3. 대기실에서 팀장 위임도 시험한다. 넘긴 사람의 준비는 해제되고 받는 사람의 준비는 유지한다. 전원 준비 후 새 팀장이 시작할 수 있어야 한다.

## 독립 모듈 QA

대기실에서는 코스를 설정하지 않는다. 시작 후 팀장이 원하는 모듈을 선택하고 모듈 안에서 설정한다. 팀장과 팀원이 같은 저장값을 보는지 확인한다. 저장은 해당 모듈을 다시 시작하고 다른 모듈의 설정은 유지한다.

| 모듈 | 확인할 행동과 결과 |
| --- | --- |
| 1 지도 | 출발/목적지 역할을 선택하고 지도를 눌러 핀을 놓는다. 내 위치 보기와 현재 위치로 지점 지정, 반경 저장을 각각 확인한다. GPS 갱신 중 핀과 반경 입력 및 포커스가 유지되고 팀원도 같은 설정을 받는다. 사진 원본은 이 단계에 표시하지 않는다. |
| 2 사진 인식 | 지도 완료 없이 바로 선택한다. 비교 원본과 물체 이름을 교체하고 촬영/이미지 선택 팝업을 확인한다. 실제 이미지를 제출해 실패 후 재촬영, 개인별 성공과 전원 전환을 확인한다. GPS 정확도 때문에 사진 제출이 막히지 않아야 한다. |
| 3 묵언 신고 | 같은 팀원을 빠르게 여러 번 신고한다. 각 요청이 즉시 벌점 1점으로 집계되고 전원에게 공유된다. 같은 요청 ID 재전송은 한 번만 집계하며 버튼 대기 시간은 없다. |
| 4 정령과 대화 | 목적지를 지도에서 정하고 GPS 범위 밖/안을 시험한다. 정령 생성, 접근과 직접 터치 및 개인별 대화를 확인한다. 한 명이 먼저 읽어도 나머지가 완료할 때까지 같은 단계에 머문다. 지원 실패 시 2D 전환과 카메라 종료를 확인한다. |
| 5 AR 길 | 출발/목적지 핀과 반경, 공간 프로젝트와 Map ID를 저장한다. 기존 카메라 방향 안내의 경유점 진행과 전원 전환을 시험한다. 바닥 고정 경로는 같은 공간의 실제 스캔과 프로젝트로 별도 검증한다. |
| 6 탐색 | 지도에서 목적지를 설정한 뒤 거리, 방향 및 색 변화와 도착 확인을 시험한다. 안내는 해당 모듈에 저장한 목적지를 사용하며 현재 GPS 및 나침반 오차를 현장에서 확인한다. |
| 7 벌점 정산 | 모듈을 이동해도 개인/팀 벌점과 신고 기록이 유지되는지, 벌점 왕과 최종 결과가 신고 기록과 일치하는지 확인한다. |

모든 장소 설정은 지도 핀으로 진행하고 숫자 입력은 도착 반경에 사용한다. 가상 좌표 조작과 가상 사진 성공/실패 버튼은 제공하지 않는다.

### 실제 지도 이동

출발점과 목적지 거리를 도착 반경의 두 배보다 멀게 정한다. 출발점에서 도착했어요가 비활성화되고 실제 이동에 따라 내 위치와 거리가 갱신되는지 확인한다. 최근 30초 이내 측정, GPS 오차가 반경 이하, 목적지 반경 안 조건을 통과하면 버튼이 활성화된다. 각자 버튼을 누르고 전원 완료 후 함께 전환한다.

위치 권한 거절, 오래된 측정, 화면 복귀 및 네트워크 재접속도 시험한다. 최신 측정으로 복구되면 도착을 다시 판정해야 한다.

## 고정 코스 QA

관리자가 /tracks에서 복지관, 광운스퀘어, 비마관 앞과 풋살장 핀 및 반경, 실제 에어팟 기준 원본을 저장하고 방을 만든다. 실제 현장 데이터와 자동 QA용 좌표/이미지를 구분한다. 자동 QA의 합성 자료는 로컬 카탈로그에서만 사용하고 원래 내용을 복원한다. 실사이트 카탈로그 QA는 읽기 전용으로 진행한다.

| 순서 | 장소 또는 구간 | 확인할 결과 |
| --- | --- | --- |
| 1 | 복지관 → 광운스퀘어 | 2D 지도와 전원 도착 확인 |
| 2 | 광운스퀘어 | 생성 당시 에어팟 원본 표시. 각자의 지도 도착 기록이 있어야 사진 판정을 시작하고 전원 성공 후 전환 |
| 3 | 묵언 안내 → 비마관 앞까지 이동 | 안내 완료 후 AR 길 단계에서 신고도 계속 사용. 경유점과 정령 지점의 전원 도착 확인 |
| 4 | 비마관 앞 | 솥고집 정령 생성/터치, 개인별 고정 대화 및 전원 완료 |
| 5 | 숨은 카페 탐색 → 풋살장 | 거리와 방향으로 목적지 탐색. 참가자 안내에 실제 목적지 좌표와 풋살장 이름을 숨기고 전원 도착 후 정산 |
| 6 | 벌점 정산 | 이동 중 신고를 포함한 개인 및 팀 결과 확인 |

방 안에서 고정 장소, 사진과 스토리를 바꿀 수 없어야 한다. 관리자가 카탈로그를 수정해도 기존 방과 재접속 화면은 생성 당시 버전을 유지한다. 다른 관리자가 먼저 수정하면 오래된 화면의 저장/방 생성은 거절하고 최신 버전을 다시 확인한다.

## 단계 조작과 초기화

팀장만 원하는 모듈 선택, 이전/다음 및 현재 단계 초기화를 조작한다. 일부 참가자가 미완료이거나 일반 요청을 기다려도 조작 결과가 전원에게 공유되어야 한다. 단계 이동과 설정 변경 뒤 늦은 소켓/사진 응답이 새 진행을 바꾸지 않는지 확인한다. 정령 화면을 벗어나면 카메라와 AR 자원을 정리한다.

| 조작 | 유지하거나 다시 시작할 상태 |
| --- | --- |
| 모듈 이동 | 방, 참가자, 모듈별 설정과 기준 사진을 유지한다. 선택한 모듈을 다시 시험하며 신고와 벌점은 정산으로 이어진다. |
| 현재 단계 초기화 | 해당 단계의 완료와 실행 기록을 다시 시작한다. 묵언 단계 자체를 초기화하면 신고와 벌점도 비운다. |
| 독립 모듈 방 전체 초기화 | 같은 링크/방 이름을 유지하고 참가자, 팀장, 준비, 입장 정보와 진행을 삭제한다. 설정과 기준 사진은 기본값으로 돌아간다. |
| 고정 코스 방 전체 초기화 | 참가자와 진행은 삭제하고 생성 당시 장소, 사진, 스토리와 버전은 유지한다. |

전체 초기화 후 접속 중인 사람과 나중에 복귀한 사람 모두 닉네임부터 다시 입력한다. 첫 재입장자가 새 팀장이며 전원 준비 후 시작한다. 취소는 기존 상태를 유지하고 다른 방의 입장 정보도 유지한다.

## 자동 검증과 현장 검증의 경계

product/game-lab에서 npm run check와 npm test로 문법 및 상태, 요청 격리, 센서 자원 정리와 AI 응답 해석을 확인한다. 실행 중인 Worker의 팀 공유와 재접속은 npm run test:socket으로 확인한다.

브라우저 QA는 test:browser:modules, test:browser:tracks, test:browser:sensors와 방 목록/신청/공간 AR 준비 화면의 전용 스크립트를 사용한다. 생성한 QA 방은 삭제한다. 지도에 주입한 GPS, 모의 카메라/사진 응답과 화면 캡처는 사용 흐름의 근거이며 현장 이동이나 AI 인식 정확도의 근거가 아니다.

사진 인증은 실제 물체를 각도, 배경과 조명을 바꾸어 촬영하고 다른 물체/빈 화면의 거절 사례도 기록한다. 촬영과 저장 이미지 선택은 모두 입력 방식이다. 선택 이미지나 화면 캡처의 판정 성공만으로 현재 장소에 있다고 인정하지 않는다. 고정 코스는 앞 단계 GPS 도착 기록과 결합하고 독립 사진 시험은 물체 인식만 확인한다.

Android 외부 Chrome과 iPhone 외부 Safari에서 실제 GPS, 나침반, 카메라 권한 및 정령 추적을 확인한다. 공간 AR의 실제 기기 안정성과 Mattercraft/Immersal의 바닥 경로 고정은 현장 통과 전까지 미검증으로 표시한다. GPS/카메라 방향 안내가 된다는 사실과 바닥에 길이 고정됐다는 사실은 구분한다.
