## Test Lab 정의와 시작 절차

Test Lab은 특정 게임을 핸드폰으로 팀과 함께 진행하는 데 필요한 여러 모듈을 검증하는 도구의 집합이다.

| ID | 정책 |
| --- | --- |
| LOBBY-01 | 참가자는 같은 테스트 방 링크로 닉네임을 입력해 입장한다. 처음 입장한 사람이 팀장이 되며 참가 인원에 상한을 두지 않는다. |
| LOBBY-02 | 팀장을 포함한 모든 참가자가 준비 완료를 누르면 팀장이 테스트를 시작한다. 시작과 테스트 단계는 서버 상태를 기준으로 전원이 공유한다. |
| LOBBY-03 | 한 명도 같은 입장, 준비 완료 및 팀장 시작 절차로 시험한다. 별도의 혼자 시작 절차 없이 첫 입장자가 준비 완료 후 시작한다. |
| LOBBY-04 | 준비를 취소하면 전원 준비 조건이 해제된다. 팀장을 넘긴 사람의 준비는 해제하고 받는 사람의 기존 준비 상태는 유지한다. |

대기실은 참가자와 준비 상태, 준비 완료 및 테스트 시작하기를 제공한다. 시작 후 팀장이 현재 모듈 안에서 설정을 저장하고 전원이 같은 조건으로 지도, 사진 인식, 신고, 정령과 개인 이야기, AR 길, 방향 탐색 및 벌점 정산을 시험한다.

## 테스트 단계 이동과 현재 단계 초기화

| ID | 정책 |
| --- | --- |
| STAGE-01 | 진행 중인 테스트 방의 팀장은 모듈을 직접 선택하거나 이전 및 다음 단계로 전원을 이동시키고 현재 단계를 초기화한다. 모든 참가자는 같은 현재 모듈을 공유한다. |
| STAGE-02 | 모듈별 설정, 방, 참가자, 팀장, 준비 상태, 입장 토큰 및 기준 사진을 유지한다. 모듈 선택은 이전 모듈의 완료 조건 없이 가능하고 선택한 모듈의 실제 판정 조건을 사용한다. |
| STAGE-03 | 모듈 선택과 이동은 현재 완료 상태 및 목적 모듈의 실행 기록을 비운다. 신고와 벌점은 모듈 사이에 유지하여 정산에 반영한다. 묵언 모듈의 현재 단계 초기화 또는 설정 저장은 신고 및 벌점도 비운다. |
| STAGE-04 | 단계 제어마다 새로운 실행 ID를 발급하고 이전 요청 목록과 사진 작업을 지운다. 참가자의 연결을 유지하며 이전 실행의 소켓 요청과 늦은 사진 판정이 새 진행을 변경하지 못하게 한다. |

모듈 직접 선택과 화면의 이전 테스트, 다음 테스트 및 현재 단계 초기화는 팀장에게 제공한다. 단계 제어는 새 실행 ID로 개인 이야기와 사진 입력 및 AR 실행을 다시 준비한다. 엔딩에서 이전 단계로 돌아온 실제 GPS 참가자는 위치 연결을 다시 눌러 새 위치를 받는다.

| COURSE-01 | 출발지와 목적지는 지도에서 선택하고 지도를 다시 눌러 핀을 옮긴다. 현재 위치와 GPS 오차 범위를 지도에 표시하며 현재 위치를 중심으로 보거나 선택한 지점으로 지정할 수 있다. 도착 반경은 기존 입력으로 조정한다. |
| COURSE-02 | 실제 GPS 지도 코스는 출발점과 목적지 거리가 도착 반경의 두 배보다 멀어야 설정 저장 및 지도 완료가 가능하다. 대기실 시작은 코스 설정을 요구하지 않는다. |
| COURSE-03 | 지도 단계에서 GPS를 연결하고 기존 정확도, 최근 측정 시각 및 목적지 반경 검사를 통과하면 도착 가능 상태를 표시한다. 참가자가 도착했어요를 누르면 서버 도착 기록을 저장한다. |
| COURSE-04 | GPS 지도 코스의 출발점과 목적지 영역이 겹치면 지도 완료를 거절하고 지도 모듈에서 목적지를 다시 선택하도록 안내한다. 다른 모듈은 각각 저장한 목적지와 도착 반경을 사용한다. |

GPS 지도 단계에 진입하면 각 참가자의 실제 위치 연결을 시작한다. 위치 감시와 활성 화면에서의 새 측정 요청으로 위치를 갱신하고 측정 시각이 30초를 넘으면 도착 판정을 기다린다. 지도에서 출발 영역과 도착 영역을 구분하고 최신 위치가 도착 조건을 통과하면 도착 가능 표시를 제공한다. 도착했어요를 눌러 개인 완료를 확정하고 전원 완료 후 다음 단계로 함께 이동한다.

## 사진 인증 정책

| 대상 | 촬영 및 판정 기준 |
| --- | --- |
| 파란 뚜껑 생수병 | 등록된 기준 사진의 중심 물체와 종류, 형태 및 색 특징이 맞는 물체를 촬영한다. 각도, 배경과 조명 차이는 허용하며 용량 표기를 요구하지 않는다. |
| 500ml 생수병 | 생수병과 500ml, 500mL 또는 0.5L 용량 표기가 읽히도록 촬영한다. 컵, 빈 병, 다른 음료, 다른 용량 및 표기가 불명확한 사진은 재촬영한다. |

독립 모듈 시험의 사진은 실제 이미지와 기준 물체의 인식만 시험한다. 지도 도착 기록과 현재 GPS 정확도를 사진 판정의 선행 조건으로 사용하지 않는다. 고정 캠퍼스 트랙과 운영 트랙은 앞 단계 지도 도착 기록과 기준 물체 사진을 결합하는 정책을 사용한다.

독립 모듈 방의 기준 사진 원본은 인증된 참가자만 조회하는 저장소에 보관하고 사진 모듈에서 비교 원본을 표시한다. 팀장은 사진 모듈에서 기준 물체 이름과 원본 사진을 교체한다. 교체 시 전원의 사진 완료 및 판정 기록을 비우고 새 실행 ID로 이전 사진 작업을 격리한다. 독립 모듈 방의 전체 초기화는 팀 기준 사진을 삭제하고 기본 기준 사진을 적용한다. 고정 트랙 방은 생성 당시 기준 사진을 유지한다.

| 이전 버전 | 이전 기본 대상 | 현재 기본 대상 |
| --- | --- | --- |
| 3 미만 | 컵 | 파란 뚜껑 생수병 |
| 4 미만 | 500ml 생수병 | 파란 뚜껑 생수병 |

이전 기본 대상 방은 참가자와 각 모듈의 설정을 유지하며 현재 기본 대상으로 변경한다. 직접 등록한 기준 물체는 유지한다. 새 정책의 사진 모듈에서는 이전 지도 완료 기록과 독립적으로 판정한다.

## 적용 범위와 검증

별도 nonol-game-lab 테스트 사이트에 적용한다. 제품의 공유 대기실 정책 nonol-room-v1은 product/game/public/room-policy.json에서 관리한다.

초기화 전후 참가자와 설정, 새로운 첫 팀장, 오프라인 참가자의 복귀, 기존 토큰과 지연 요청 거절을 단위, 소켓 및 브라우저 시험으로 검증한다. 운영 코스의 좌표와 판정 규칙은 별도 합의 후 연결한다.
