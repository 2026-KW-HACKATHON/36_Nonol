# 공간 AR 길 안내 정책 SSOT

정책 ID: nonol-spatial-route-v1
확정 시각: 2026-10-09 03:57:10 KST
상태: Mattercraft와 Immersal 선택 확정, 짧은 테스트 구간 준비. 실제 공간 스캔과 AR 현장 검증 대기.

## 목표와 준비 순서

카메라를 돌리거나 사용자가 이동해도 바닥에 길이 붙어 있는 경험을 검증한다. 사용자가 선택한 Mattercraft World Tracking과 Immersal VPS를 사용한다. VPS는 카메라 이미지로 스캔한 공간의 위치와 자세를 인식하는 Visual Positioning System이다.

1. 추천 시험 구간은 벽, 기둥 및 간판 등의 특징이 있는 평평한 10~20m 보행 구간이다. 이 길이는 첫 시험의 추천이며 제품 정책 제한이 아니다. 출발, 한 번의 회전과 도착 지점을 포함한다.
2. Immersal 계정과 Mapper 앱을 준비한다. Manual Mode에서 이동하며 겹치는 주변 사진을 촬영하고 업로드한다. 포털에서 처리 상태 done과 Map ID를 확인한다.
3. Mattercraft의 Immersal VPS 템플릿에 Map ID와 개발 토큰을 설정한다. 실제 지도 모델에서 바닥 높이, 출발, 회전 및 도착의 로컬 x, y, z 좌표를 기록한다. 계정과 배포 플랜은 실제 사용 전에 확인한다.
4. 코드 연결과 현장 기기 검증을 마친 뒤 Test Lab의 팀 퀘스트에 연결한다. 현재 준비 페이지는 계정 토큰과 카메라 이미지를 수집하지 않는다.

## 시험 모듈의 동작

경로는 스캔한 맵의 로컬 좌표계에서 미터 단위로 정의한다. 위도와 경도만으로 바닥 높이를 지정하지 않는다. 첫 모듈은 같은 높이의 바닥에 미리 지정한 경로를 표시하며 자동 도로 경로 계산과 다층 안내는 후속 범위다.

Immersal 공간 인식 완료와 WorldTracker의 GOOD 추적 상태를 함께 확인한다. 인식 전, 추적 제한, 카메라 부재 및 숨겨진 문서에서는 길을 숨기고 도착을 판정하지 않는다. 추적 복구와 새 VPS 성공 이벤트를 확인한 뒤 같은 맵 좌표에서 이어간다. 엔진의 재인식과 보정에 따른 흔들림은 현장에서 측정한다.

경로는 ImmersalAnchorGroup 바로 아래 Mattercraft Group의 실제 자식 좌표계에 배치한다. 해당 Group의 위치와 회전은 0, 크기는 1로 유지한다. 공개 appendChild로 연결된 그룹은 SDK 내부 공간 변환을 상속한다. 앵커 바깥 element에 직접 배치하면 같은 공간 변환을 받지 않으므로 사용하지 않는다.

첫 좌표는 출발, 이후 좌표는 순서대로 통과할 지점이다. 시험 기본값은 길 너비 0.35m, 도착 반경 0.8m와 연속 유지 1.5초다. 추적 손실, 반경 이탈 및 1초보다 긴 갱신 중단은 유지 시간을 다시 시작한다. 완료 이벤트는 한 번만 발생하며 현재 모듈에서는 개인 시험 결과다. 팀 서버의 미션 완료로 자동 인정하지 않는다.

## 소스와 연결

원본은 game-lab/public/spatial-route의 floor-route.js, mattercraft-bridge.js, route-example.json 및 MattercraftFloorRoute.ts 파일이다. 각 파일명은 261009_0355 접두사를 사용한다. 예제 좌표는 공간 스캔을 대체하지 않으며 confirmed는 false, mapId는 빈 값으로 제공한다. 실제 Map ID와 현장 맵 좌표로 수정하고 확인한 뒤 confirmed를 true로 변경한다.

Mattercraft 프로젝트에 네 파일을 같은 폴더로 추가한다. ImmersalAnchorGroup 아래에 Group을 만들고 사용자 Behavior를 추가한다. 그 Behavior에서 TypeScript 파일의 attachMattercraftFloorRoute를 import한 뒤 생성자에서 attachMattercraftFloorRoute(contextManager, instance)를 호출한다. 이 함수가 경로 Behavior를 Group에 등록하며 Group 종료 시 정리된다. Behavior는 실제 프로젝트의 Three.js, 카메라와 WorldTracker를 사용한다. 검증한 패키지는 @zcomponent/immersal 1.3.0, @zcomponent/zappar-three 4.3.4, @zcomponent/three 1.38.2 및 Three.js 0.164.0이다. 프로젝트의 실제 Three.js를 주입하며 별도 Three.js 사본을 혼합하지 않는다. 개발 토큰은 Mattercraft의 Immersal 설정에서 관리하며 이 JSON과 Git에 기록하지 않는다.

nonol:spatial-route-status는 인식, 추적과 경유점 상태를 전달하고 nonol:spatial-route-complete는 개인 시험 완료를 전달한다. 이벤트는 브라우저 내부 연결용이며 서버 권한과 현장 방문 증명의 근거로 단독 사용하지 않는다. 단계 이탈 시 Behavior를 dispose하거나 pause하고 다시 시험할 때 resetRoute를 실행한다.

## 현장 통과 조건

- 출발과 회전 및 도착에서 바닥 선이 같은 실제 지점에 유지되는지 확인한다. 눈에 보이는 오차는 실제 측정값으로 기록한다.
- 카메라를 돌린 뒤 돌아와 같은 바닥 선을 찾을 수 있는지 확인한다. 추적이 끊겼을 때 숨김과 도착 보류 및 재인식 후 복구를 확인한다.
- 경유점을 순서대로 통과하고 잠시 머물렀을 때만 완료되는지 확인한다. 앱 전환과 화면 잠금 뒤 자동 완료가 발생하지 않는지 확인한다.
- iPhone Safari와 Android Chrome의 실제 카메라, 권한 및 공간 추적을 각각 확인한다. 코드와 센서 모사 결과는 실제 AR 통과와 구분한다.
