# 묵언수행 개발 모듈과 작업 순서

갱신 시각: 2026-10-09 06:37:19 KST
기준: nonol-test-lab-v15 및 캠퍼스 고정 트랙 정의 v2.
상태: 계속 갱신하는 개발 초안. 확정 정책과 구현 상태를 구분한다.

Test Lab은 휴대폰으로 팀 게임에 필요한 모듈을 검증하는 도구의 집합이다. 운영 nonol-game과 별도 Worker 및 방 저장소를 사용한다. 검증한 모듈을 실제 묵언수행 트랙에 연결하는 단계는 별도 작업이다.

## 시작과 두 가지 시험 공간

공통 시작은 링크 입장 → 닉네임 → 팀장을 포함한 전원 준비 → 팀장 시작이다. 첫 입장자가 팀장이며 인원 상한은 없다. 혼자도 같은 절차로 시작한다. 대기실에서 팀장을 넘긴 사람의 준비는 해제하고 받는 사람의 기존 준비는 유지한다.

| 공간 | 설정과 진행 |
| --- | --- |
| 독립 모듈 방 | 대기실에서는 입장과 준비만 진행한다. 시작 후 팀장이 모듈을 고르고 그 안에서 설정한다. 팀장도 같은 저장값으로 시험하며 다른 모듈의 설정은 유지한다. 이전 모듈을 완료하지 않고 원하는 모듈을 선택할 수 있다. |
| 고정 코스 방 | 관리자가 /tracks에서 네 장소의 지도 핀, 반경과 에어팟 원본을 저장하고 방을 만든다. 장소, 원본, 스토리와 버전을 방 생성 시 고정하며 방 안에서는 수정하지 않는다. 이후 카탈로그 수정은 새 방에 적용한다. |

## 개발 모듈과 현재 상태

번호는 독립 모듈 목록이며 고정 코스의 실행 순서와 구분한다. 팀의 현재 모듈과 완료는 WebSocket 및 서버 상태로 공유한다.

| 번호 | 모듈 | 필요한 기능 | 현재 상태 |
| --- | --- | --- | --- |
| 공통 | 입장과 팀 진행 | 준비, 팀장 양도, 공동 시작, 재접속, 전원 완료와 지연 요청 격리 | 시험 구현 및 자동 QA 확인 |
| 1 | 지도 | 출발지와 목적지 핀, 현재 GPS와 팀원 위치, 반경 안 도착 확인. 사진 없이 이동만 판정 | 시험 구현 및 자동 QA 확인, 현장 이동 검증 필요 |
| 2 | 사진 인식 | 비교 원본, 촬영 또는 이미지 선택, 물체 비교, 기준 교체와 재촬영 | 실제 이미지 판정 구현, 현장 사진의 인식 정확도 검증 필요 |
| 3 | 묵언 신고 | 다른 팀원 연속 신고, 신고당 1점, 중복 요청 한 번 집계 | 대기 시간 없이 시험 구현 및 자동 QA 확인 |
| 4 | 정령과 대화 | 지정 장소의 GPS 판정, 정령 생성/접근/터치, 각자 대화, 기기 미지원 시 2D | 시험 구현, 실제 기기의 공간 추적 검증 필요 |
| 5 | AR 길 | 출발과 목적지, 경유점 도착, 공간 스캔 Map ID와 Mattercraft 프로젝트 연결 | 카메라 방향 안내 및 공간 AR 연결 준비 구현, 바닥 고정 경로 현장 검증 필요 |
| 6 | 거리와 방향 탐색 | 지정 목적지까지 거리와 방향 및 색 변화, 각자 도착 확인 | 시험 구현 및 자동 QA 확인, 실제 GPS/나침반 검증 필요 |
| 7 | 벌점 정산 | 개인과 팀 벌점, 벌점 왕 및 최종 결과. 금액 정산과 구분 | 시험 구현 및 자동 QA 확인 |
| 별도 | 운영 연결 | 실제 신청 DB와 팀 연결, 카카오톡 발송, 식사/카페 노놀판과 완주 보상 | 운영 연결 대기 |

위치 모듈은 실제 GPS를 사용한다. 팀장은 지도에서 지점을 눌러 지정하고 다시 눌러 수정한다. 현재 위치 보기와 현재 위치를 선택 지점으로 지정하기는 별도 행동이다. 반경 입력은 유지하며 위도/경도 숫자 입력은 제공하지 않는다. GPS 갱신은 선택 핀과 입력 및 포커스를 유지한다.

지도는 출발과 목적지의 거리가 도착 반경의 두 배보다 멀어야 저장 및 완료할 수 있다. 최근 30초 이내 GPS와 정확도 및 목적지 반경 조건을 통과한 참가자가 도착했어요를 누르면 도착을 기록한다. 가상 위치 버튼과 가상 사진 성공/실패 판정은 제공하지 않는다.

## 고정 코스와 다음 작업

복지관 출발 → 광운스퀘어 지도 도착 및 에어팟 사진 → 묵언 안내 → 비마관 앞까지 이동과 신고 → 솥고집 정령 대화 → 거리와 방향으로 카페 역할의 풋살장 탐색 → 벌점 정산.

고정 코스 사진은 각자의 앞 단계 지도 도착 기록과 기준 사진을 결합한다. 독립 사진 모듈은 지도 도착과 GPS 정확도 조건 없이 물체 인식을 시험한다. AR 산책 중 신고를 함께 사용하며 바닥 경로와 기존 카메라 방향 안내는 별도 결과로 확인한다.

1. 관리자가 현장에서 네 장소의 핀과 반경 및 실제 에어팟 기준 사진을 등록한다.
2. 실제 휴대폰으로 지도, 사진, 신고, 탐색과 엔딩을 연결해 완주하고 오차와 실패 사례를 기록한다.
3. 광운스퀘어에서 비마관 앞까지 짧은 구간을 스캔하고 Map ID와 Mattercraft 프로젝트로 바닥 고정 경로를 검증한다.
4. 검증한 모듈을 운영 장소 및 서비스 흐름에 연결한다. 운영 인증과 벌점 및 엔딩 세부 조건의 미확정 항목은 별도 합의한다.

## 정책과 변경 관리

팀장만 모듈 선택, 이전/다음 이동 및 현재 단계 초기화를 조작한다. 설정 저장은 해당 모듈의 완료를 비우고 새 실행 ID를 발급한다. 이동 시 신고와 벌점은 유지하며 묵언 단계 자체를 초기화하면 신고와 벌점도 비운다.

방 전체 초기화는 같은 링크와 방 이름을 유지하며 전원을 닉네임 입력으로 돌려보낸다. 참가자, 입장 정보와 진행은 삭제하고 첫 재입장자가 새 팀장이 된다. 독립 모듈 방은 설정과 기준 사진도 기본값으로 돌아가며 고정 코스 방은 생성 당시 장소, 사진, 스토리와 버전을 유지한다.
