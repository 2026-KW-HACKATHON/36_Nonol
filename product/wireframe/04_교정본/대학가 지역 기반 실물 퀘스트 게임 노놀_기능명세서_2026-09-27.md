최신 사용자 결정이 원본의 자동 생성 내용보다 우선한다.

## 1. 제품 정의와 확정 사항

노놀은 동네의 재미를 실제 장소에서 수행하는 퀘스트로 만들고, 사용자가 미션을 마치면 스탬프를 얻는 지역 기반 실물 퀘스트 게임이다. 초기 지역은 노원구 월계동이며 친구와 함께하는 경험을 중심으로 기획한다.

| ID | 확정 기준 |
| --- | --- |
| P-01 | 참가비는 1인 10,000원이다 |
| P-02 | 참가비 10,000원 전액을 결식 아동 후원에 사용한다. 운영비를 차감한 잔액이나 결제액의 일부로 표현하지 않는다 |
| P-03 | 가입자 1명당 팀이 1,000원을 기부하는 계획도 유지한다. 참가비 후원과 별도 항목으로 표시한다 |
| P-04 | 폰에서 해당 장소의 미션을 안내받고, 실제 미션을 수행한 뒤, 다음 장소로 떠나기 전에 현장의 NFC 태그로 마무리 인증한다 |
| P-05 | 인증 후 폰에서 다음 장소와 진행 내용을 안내한다. NFC 태그를 찍는 것만으로 미션 수행을 대신하지 않는다 |
| P-06 | 퀘스트의 모든 필수 미션과 마무리 인증 조건을 충족하면 스탬프를 얻는다 |
| P-07 | 포인트 제도는 없다. 포인트 적립, 교환, 차감 및 포인트 보상을 넣지 않는다 |
| P-08 | 블록체인은 Base L2 연결 예정이다. 사용자 설명상 로컬 검증은 완료했고 테스트넷 배포와 추가 검증은 추후 진행한다 |
| P-09 | 기술은 현장 경험과 스탬프 기록을 뒷받침하고 홍보에 활용한다. 사람들이 참여할 이유와 재미가 설명의 중심이다 |

초기 유료 수익 기부라는 이전 표현은 참가비 전액 결식 아동 후원으로 구체화되었다. 이를 순이익 기부 또는 10% 기부로 되돌리지 않는다. 후원 기관, 집행일, 증빙 공개 방식은 아직 미정이다. 가입자당 기부의 한도와 집행 조건, 참가비 후원과의 합산 방식도 별도 확정이 필요하다.

## 2. 문제와 요구사항의 연결

관찰된 고객 근거가 제시되지 않은 내용은 가설로 남긴다. 아래 표가 있다는 사실만으로 수요가 검증된 것은 아니다.

| 문제 가설 | 사용자에게 필요한 것 | 요구사항과 화면 | 검증할 것 |
| --- | --- | --- | --- |
| 동네 정보가 흩어져 있고 방문할 계기가 부족하다 | 친구와 실제로 할 활동을 이해하고 참여를 결정한다 | R-01 퀘스트 소개, 활동 내용과 참가비 안내 | 소개 후 신청 여부, 참여하거나 이탈한 이유 |
| 장소 목록만으로 함께 할 행동이 정해지지 않는다 | 현장에서 무엇을 할지 구체적으로 안내받는다 | R-03 미션 안내와 수행 화면 | 안내 이해 여부, 미션 수행과 중도 이탈 |
| 현장 참여와 완료 기록을 연결할 필요가 있다 | 미션을 마친 자리에서 인증하고 다음 진행을 안다 | R-04 NFC 마무리 인증, 다음 장소 안내 | 인증 성공과 실패, 진행 중단 사유 |
| 함께 한 경험을 남기고 싶다는 가설이 있다 | 완료한 퀘스트를 스탬프로 기록한다 | R-05 스탬프와 여권 | 기록의 가치, 다른 퀘스트 참여 의사와 실제 행동 |
| 재미있는 참여를 좋은 일과 연결하고 싶다 | 참가비가 어디에 쓰이는지 이해한다 | R-02 참가비와 R-06 후원 안내 | 후원 취지 이해, 참여 동기와 신뢰 |

기부와 스탬프가 참여를 높인다는 것은 검증할 가설이다. 선한 취지가 자동으로 수익이나 사업 확장을 보장한다고 쓰지 않는다.

## 3. 사용자와 초기 운영 범위

- 친구와 함께 새로운 놀거리를 찾는 모임을 초기 대상으로 본다.
- 기존 제품 맥락의 2~4명 팀을 참고하되, 인원 미달, 중도 이탈, 대표자 결제의 운영 정책은 확정 전이다.
- 여러 대학가의 코스를 이미 운영하는 것처럼 표현하지 않는다.
- 첫 회차의 실제 코스 이름, 장소, 개별 미션, 일정과 소요 시간은 확인한 운영 자료를 연결한다. 시안의 장소 1~3은 기존 3곳 코스 개념을 설명하기 위한 예시이지 제휴 매장 명단이 아니다.
- 단일 회차 신청부터 시작할지 여러 퀘스트를 탐색하게 할지는 미정이다. 화면 시안은 하나의 코스로 진행을 설명하며 사업 범위를 확정하지 않는다.
- 관심사 온보딩과 사용자 DB 기반 콘텐츠 개선은 방향으로 유지한다. 구체적 문항, 필수 여부, 동의와 보관 범위는 별도 기획한다. 검색 필터만으로 관심사 데이터 수집이 구현되었다고 하지 않는다.

## 4. 기능별 명세

### R-01 퀘스트 소개와 참여 결정

사용자는 지역, 실제 활동 내용, 참가 조건, 참가비와 후원 용도를 확인한다. 일정, 장소와 예상 소요 시간은 검증된 운영 정보만 표시한다.

수용 기준:
- 참가비는 모든 화면에서 1인 10,000원으로 일치한다.
- 참가비 전액 결식 아동 후원이라는 사실을 참여 결정 전에 볼 수 있다.
- 퀘스트가 장소 방문만인지 별도의 활동을 포함하는지 미션 내용으로 이해할 수 있다.
- 상세 미정 코스를 판매 가능한 실제 상품처럼 표시하지 않는다.
- 비로그인 소개 열람을 허용하는 방향을 제안한다. 실제 인증 방식은 별도 결정하며 로그인 필수 흐름과 충돌하지 않게 한다.

### R-02 신청, 팀과 참가비 확인

참가비 산정은 인원 × 10,000원이다. 예를 들어 2명은 20,000원이며 해당 참가비 전액이 결식 아동 후원 대상이다. 팀당 정액 10,000원으로 표시하지 않는다.

수용 기준:
- 인원, 1인 단가, 총 참가비, 전액 후원 용도가 같은 화면에 표시된다.
- 가입자당 팀 부담 1,000원 기부를 참가자에게 추가 청구하지 않는다.
- 대표 일괄 결제와 개인별 결제 중 어느 방식을 쓸지는 미정으로 남긴다.
- 결제 수단, 완료 확인 방식, 취소와 환불, 결제 후 인원 변경은 확정 전에 운영을 시작하지 않는다.
- 실제 결제 또는 운영자 확인 결과 없이 결제 완료라고 처리하지 않는다.
- 정적 시안은 금액 확인만 보여주며 실제 결제나 신청 저장을 수행하지 않는다.

### R-03 현장 미션 안내와 수행

폰에서 현재 장소의 미션 내용, 해야 할 활동, 완료 조건을 알려준다. 사용자는 미션을 먼저 수행한다. 사진, 답변, 역할 수행 등 구체적 콘텐츠와 완료 판정 방식은 실제 운영 코스에 맞춘다.

수용 기준:
- 미션 수행과 NFC 마무리 인증은 화면과 상태에서 별도 단계다.
- NFC 안내에는 "미션을 마친 뒤, 다음 장소로 떠나기 전에 태그하세요"라는 순서가 드러난다.
- 미션 수행 조건이 충족되지 않으면 NFC 인증만으로 다음 단계에 진입할 수 없다.
- 미션 완료 판정 방식이 미정이면 자가 확인, 제출물 확인 또는 운영자 확인 중 하나가 구현된 것으로 단정하지 않는다.
- 네트워크 오류나 재진입 시 이미 저장된 진행 기록을 잃지 않는 것이 요구사항이다.

### R-04 NFC 마무리 인증과 다음 장소 안내

현장에서 미션을 마친 사용자가 출발 전에 NFC 태그를 인식한다. 서버는 현재 사용자, 퀘스트, 장소와 태그의 유효성을 확인하며, 방문 인증의 성공이 실제로 모든 활동을 수행했다는 별도 증거를 자동으로 대체하지는 않는다.

상태의 순서:
미션 안내 → 수행 조건 충족 → NFC 마무리 인증 대기 → 인증 성공 → 다음 장소 안내.
마지막 장소라면 인증 성공 후 전체 완료 조건을 확인하고 스탬프로 이동한다.

수용 기준:
- 다른 장소의 태그, 유효하지 않은 요청 또는 수행 조건 미충족 요청으로 진행 상태를 앞당기지 않는다.
- 태그 인식 실패, 검증 실패, 네트워크 실패를 성공으로 표시하지 않는다.
- 실패하면 해당 자리에서 다시 시도하도록 안내하고 이전 수행 기록을 유지한다.
- 반복 인증은 같은 완료 기록이나 스탬프를 중복 생성하지 않는다.
- 다음 장소가 있으면 다음 장소와 진행 안내를 폰에서 표시한다.
- NFC를 사용할 수 없는 기기의 대체 절차는 운영 정책으로 확정해야 한다. 임의의 우회 인증을 자동 승인하지 않는다.
- 팀 전원 또는 대표자의 인증 여부, 팀원 이탈 시 처리 방식은 별도 확정한다.

### R-05 스탬프 획득과 여권

퀘스트의 모든 필수 미션과 마무리 인증 조건을 충족했을 때 완료 스탬프를 표시한다. 개별 장소에서 태그할 때마다 퀘스트 완료 스탬프를 발급하지 않는다.

수용 기준:
- 완료한 퀘스트와 획득 기록을 연결해 보여준다.
- 중간 미션의 인증 성공 화면에서는 다음 장소로 이동하고, 마지막 조건 충족 시에만 스탬프 획득을 안내한다.
- 포인트, 등급, 교환, 추가 보상 해제는 만들지 않는다.
- 스탬프를 팀 단위로 귀속할지 각 참가자에게 귀속할지, 재참여 시 중복 획득을 허용할지는 확정 전이다.
- 블록체인 기록 상태와 서비스 내 완료 기록을 구분한다.
- Base 테스트넷과 메인넷의 미배포 상태를 발급 완료로 표현하지 않는다.
- 스탬프 유일성은 고유 식별, 중복 방지, 양도 제한 중 실제로 보장하는 속성을 확정해 설명한다.

### R-06 후원 안내

참가비 전액 결식 아동 후원과 가입자당 팀 부담 기부를 분리해서 설명한다.

수용 기준:
- 참가비: 1인 10,000원, 전액 결식 아동 후원.
- 가입 캠페인: 가입자 1명당 팀이 1,000원 부담.
- 후원 예정액과 실제 집행액을 구분한다.
- 기관, 집행일, 증빙 방식은 확정된 값만 표시한다. 정해지기 전에는 안내 예정으로 표시한다.
- 광고 참여 적립, 결제액 10% 적립, 청년 문화 지원 등 합의되지 않은 정책을 넣지 않는다.
- 운영비와 결제 수수료를 이유로 참가비 후원액을 줄이지 않는다. 비용 부담 주체와 조달 방법은 별도 결정한다.

## 6. 검증과 발표

- 논리: 왜 단순 장소 목록 대신 함께 할 활동이 필요한지 사용자 관찰로 확인한다.
- 경험: 미션 내용의 이해, 수행의 재미, 인증의 불편, 완주와 재참여를 확인한다.
- 기부: 참여 동기와 후원 취지를 이해했는지 확인한다.
- 재현성: 동일 요구사항 ID로 화면과 정상 및 실패 사례를 연결한다.
- 지표: 소개 대비 신청, 신청 대비 실제 참여, 시작 대비 완주, NFC 실패율과 원인, 재참여. 측정 분모와 기간은 실험 전에 정한다.
- 확인되지 않은 가입자, 매출, 후원 집행액, 스탬프 개수와 날짜는 성과처럼 넣지 않는다.

## 7. 남은 운영 결정

실제 코스와 미션, 참가 일정과 시간, 로그인 및 가입 방식, 관심사 문항, 팀 완료 기준과 인원 변경, 결제 방식과 환불, 후원 기관과 집행 일정, 가입자당 기부 한도 및 합산 방식, 스탬프 귀속과 중복 정책, NFC 불가 기기 대응은 아직 확정해야 한다.

이 항목들은 사용자가 확정한 참가비, 전액 후원, 미션 후 NFC 순서를 바꾸는 근거가 아니다.
