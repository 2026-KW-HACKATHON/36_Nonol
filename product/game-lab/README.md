# 노놀 별도 테스트 사이트

테스트 주소: https://nonol-game-lab.1991knet.workers.dev

Test Lab은 특정 게임을 핸드폰으로 팀과 함께 진행하는 데 필요한 여러 모듈을 검증하는 도구의 집합이다.

제품과 별도 Worker, 방 저장소 및 관리자 비밀값을 사용한다. 제품 주소의 방과 테스트 주소의 방은 서로 공유하지 않는다. 참가자는 기본 주소의 방 목록 또는 발급된 테스트 링크로 입장한다.

## 방 목록과 관리자 정리

기본 주소의 첫 화면에서 현재 방 이름, 인원, 진행 상태와 단계를 조회하고 방 이름을 검색하거나 목록을 새로고침한다. 방 들어가기를 누르면 기존 닉네임 입장과 준비 절차를 사용한다. 기존 방은 목록 저장소에 등록하고 새 방은 생성 시 자동으로 등록한다.

관리자 로그인의 비밀번호는 Cloudflare Worker Secret NONOL_BASIC_KEY를 사용한다. 관리 API의 Bearer 인증은 ROOM_ADMIN_KEY를 사용한다. 서버가 확인한 뒤 HttpOnly 세션을 발급하며 비밀번호를 브라우저 저장소에 보관하지 않는다. 관리자 로그아웃은 세션을 해제한다. 관리자 방 삭제는 팀장과 관계없이 참가자 및 방 데이터를 지우고 현재 접속자를 방 목록으로 돌려보낸다. 삭제된 방의 링크는 재입장할 수 없으며 전역 기본 기준 사진 저장소는 유지한다. 팀장 방 전체 초기화는 같은 링크를 유지하는 기존 절차다.

## 시험 흐름

1명부터 같은 링크의 대기실에서 시험한다. 처음 입장한 사람이 팀장이고, 혼자도 준비 완료를 누른 뒤 테스트 시작하기를 누른다. 여러 명일 때는 팀장을 포함한 전원이 준비해야 팀장이 시작할 수 있다. 준비와 시작 버튼은 코스 및 기준 사진 설정보다 먼저 제공한다. 준비 취소하기를 누르면 시작 조건이 해제된다.

닉네임 → 전원 준비 → 팀장 시작 → 2D 지도 → 사진 인증 → 묵언 신고 → 정령과 각자 이야기 → 카메라 경유점 안내 → 지도 없는 방향 탐색 → 벌점 엔딩.

시험은 실제 GPS와 실제 사진을 사용한다. 위치 감시는 각 기기의 측정 시각과 함께 좌표를 보내며 30초 이내의 측정으로 도착을 판정한다. 화면이 활성화된 동안 위치를 감시하고 측정이 멈추면 새 측정을 요청한다. 화면 복귀와 위치 모듈 전환 시 GPS와 방향 센서를 다시 연결한다. 휴대폰 화면 잠금 및 브라우저 백그라운드에서는 위치 갱신이 중단될 수 있다.

시작 후 팀장이 원하는 모듈을 선택하고 해당 모듈 안에서 장소 및 도착 반경이나 기준 사진을 저장한다. 장소는 지도에서 선택하고 다시 눌러 조정한다. 실제 현재 위치와 GPS 오차 범위를 표시하며 내 위치 보기와 현재 위치로 지점 지정은 별도 버튼으로 제공한다. 위치 갱신은 선택 핀과 반경 입력 및 포커스를 유지한다. 팀장도 팀원과 같은 설정으로 시험한다. 지도 모듈은 원 안의 실제 GPS 도착만 검사하고 사진을 표시하지 않는다. 사진 모듈은 비교 원본과 실제 이미지 인식을 독립적으로 시험한다. 사진 버튼은 촬영, 이미지 선택 및 취소 메뉴를 제공한다. 신고는 새 요청마다 바로 벌점을 반영하고 같은 요청의 재전송은 한 번만 처리한다. 인원 상한은 없다.

실제 GPS 지도 코스의 출발과 도착 거리는 도착 반경의 두 배보다 멀게 설정한다. 지도 단계의 최신 위치가 조건을 충족하면 도착 가능 상태를 표시한다. 각자가 도착했어요를 눌러 확정하고 전원 완료 후 다음 단계로 함께 이동한다.

## 고정 코스 연결 시험

/tracks에서 관리자 로그인 후 복지관, 광운스퀘어, 비마관 앞 및 풋살장의 기준점과 실제 에어팟 사진을 한 번 등록한다. 지도에서 장소를 선택한 뒤 핀을 고르고 다시 눌러 조정한다. 현재 위치와 GPS 오차 범위를 함께 표시하며 해당 장소의 현재 GPS로 지정할 수 있다. 위도 및 경도 숫자를 별도로 입력하지 않는다. 도착 반경 입력은 유지한다. 공개 캠퍼스 안내에서 확인되지 않은 출입구 좌표는 초기값으로 확정하지 않으며 등록 전에는 초안 상태다.

복지관 출발 → 광운스퀘어 지도 도착과 에어팟 사진 인증 → 묵언 안내와 비마관 앞까지 이동 및 신고 → 솥고집 정령과 개인 대화 → 거리와 방향으로 풋살장 탐색 → 개인 및 팀 벌점 정산을 시험한다. 고정 코스 사진 인증은 해당 참가자의 지도 도착 기록도 확인한다. 복지관은 이층집, 광운스퀘어는 우이천 초입, 광운스퀘어에서 비마관 앞까지는 우이천, 비마관 앞은 솥고집 정령 지점, 풋살장은 카페 역할이다.

코스 저장마다 버전이 증가하고 새 방은 생성 당시 장소, 사진 원본 및 스토리를 보관한다. 기존 방은 같은 고정 설정으로 반복 시험한다. 고정 방에서는 모듈 설정과 사진 교체를 읽기 전용으로 제공하고 전체 초기화 후에도 코스 버전을 유지한다. 전원의 입장과 준비 및 팀장 시작 절차는 일반 모듈 시험과 같다.

같은 화면에서 카카오 JavaScript 키를 등록할 수 있다. 서버의 KAKAO_MAPS_JAVASCRIPT_KEY가 있으면 우선 사용하고, 없으면 관리자 저장값을 사용한다. 키와 카카오맵 사용 설정 및 SDK 도메인이 준비되면 카카오 지도로 표시한다. 누락이나 연결 실패 시 대체 지도와 설정 안내를 제공한다. 실제 카카오 SDK 및 현장 위치 검증은 유효한 키 연결 후 진행한다.

바닥 고정 AR은 해당 구간의 Immersal 공간 스캔 및 Mattercraft 프로젝트를 연결해 시험한다. 현재는 연결 준비와 별도 카메라 방향 안내를 제공한다. 수동 경유점 완료나 프로젝트 링크 열기를 바닥 고정 성공으로 집계하지 않는다.

팀장은 트랙 화면의 테스트 단계 조작에서 이전 테스트, 다음 테스트 및 현재 단계 초기화를 실행한다. 일반 미션 요청이 응답을 기다리는 중에도 단계 조작을 사용할 수 있고 중복 단계 조작은 대기한다. 버튼 바로 아래에 연결 상태, 이동 중 상태와 거절 사유를 표시한다. 전원이 같은 단계로 이동하고 참가자, 팀장, 코스 설정과 위치 및 지도 도착 기록은 유지한다. 해당 단계의 완료와 전용 기록을 초기화하고 새 실행 ID로 이전 비동기 결과를 격리한다. 묵언 단계의 초기화는 신고와 벌점, 정령 단계는 개인 만남과 이야기, 경유점 단계는 경유점 진행을 다시 시험하게 한다.

## 신청 그룹과 개인 링크 시험

관리자 로그인 후 신청 그룹과 개인 링크 만들기를 연다. 그룹 이름, 날짜, 시간과 2명 이상의 신청자 이름을 입력하면 각자의 개인 링크를 발급한다. 신청자는 본인의 링크로 입장하고 첫 입장자가 팀장이 된다. 개인 링크 소지로 신청자를 구분하며 별도 회원가입 절차를 사용하지 않는다.

각자 준비 완료와 노놀판 확인을 마치면 팀장이 시작한다. 노놀판 시험 주소는 /board?board=icheungjip-lab 이며 실제 NFC 태그에 이 주소를 기록해 시험할 수 있다. 웹에서 확인 버튼을 눌러도 같은 기록을 생성하므로 물리적 NFC 접촉을 증명하는 기능은 아니다. 전체 초기화는 신청 명단과 개인 링크를 유지하면서 입장, 준비와 태그 기록을 새로 시작한다. 관리자 방 삭제는 신청 명단도 삭제한다.

현재는 관리자가 시험용 신청 명단을 생성한다. 실제 신청 데이터베이스, 결제와 카카오톡 자동 발송 연결은 다음 개발 범위다. 개인 링크는 발급 화면에서 한 번만 전달하며 서버에는 해시를 저장한다.

## 바닥 고정 AR 길 안내 준비

/spatial-route에서 Mattercraft와 Immersal 시험 준비물, 스캔 순서와 체크리스트를 확인한다. 공개 소스는 public/spatial-route에 있으며 실제 공간 스캔, Map ID와 Mattercraft 프로젝트에 연결해 사용한다. 예제 좌표는 미확인 상태로 제공하고 자동 팀 미션 완료에는 연결하지 않는다. [공간 AR 정책 SSOT](../game/docs/261009_0355_공간AR길안내_정책_SSOT.md)에 연결과 현장 검증 조건을 기록한다.

## 원본과 구조

방 정책과 상태 로직은 ../game/public/room-policy.json과 ../game/src/room-state.js를 공유한다. public/room-policy.json은 vendor 명령으로 만드는 읽기용 사본이다. 실험 설정의 원본은 public/test-track.json이며 운영 정책 확정값과 구분한다.

테스트 정책은 public/test-track.json의 nonol-test-lab-v15, 버전 15에서 관리한다. npm run policy:render로 [정책 SSOT](../game/docs/261008_2017_테스트방_초기화_정책_SSOT.md)를 생성하며 원본의 versionHistory와 Git에 변경 이력을 남긴다. 팀장이 방 전체 초기화를 확인하면 참가자, 입장 정보와 진행이 지워진다. 일반 모듈 방은 설정이 초기화되고 고정 코스 방은 생성 당시 설정을 유지한다. 전원은 같은 링크에서 닉네임을 다시 입력하고 첫 재입장자가 새 팀장이 된다.

## 실행과 배포

```sh
npm ci
npm run dev
npm run check
npm test
npm run test:socket
npm run test:browser
npm run test:browser:sensors
npm run test:browser:directory
npm run test:browser:registration
npm run test:isolation
npm run test:browser:tracks
npm run deploy
```

로컬 포트는 8791이다. npm run deploy는 nonol-game-lab만 배포한다. 별도 ROOM_ADMIN_KEY를 .dev.vars와 테스트 Worker secret에 설정한다. ROOM_BASE_URL과 ROOM_ADMIN_KEY를 환경 변수로 지정하고 npm run room:create로 시험용 링크를 발급한다. 링크는 저장소 루트 .local/game-lab-rooms에만 저장한다.

새 환경에서는 .dev.vars.example을 .dev.vars로 복사하고 ROOM_ADMIN_KEY, NONOL_BASIC_KEY 및 KAKAO_MAPS_JAVASCRIPT_KEY를 채운다. 키 파일은 로컬에 보관한다. npm run vendor가 지도, AR 라이브러리와 라이선스 및 공용 방 정책 사본을 생성한다. dev와 deploy는 이 명령을 먼저 실행한다. 단독 브라우저 시험 전에도 npm run vendor를 실행한다.

npm run test:isolation은 삭제 API를 제공하는 별도 제품 서버와의 분리 시험이다. PRODUCT_BASE_URL 및 PRODUCT_ADMIN_KEY를 지정한다. 운영 서버 설정이 없는 해커톤 복사본에서는 미실행 사유를 출력한다. Test Lab의 상태, 소켓과 모듈 시험은 별도로 실행할 수 있다.

기존 저장소의 방 ID는 비공개 파일의 roomIds 또는 objectIds 배열로 준비하고 ROOM_ADMIN_KEY와 ROOM_BASE_URL을 지정해 npm run rooms:import -- 파일경로로 목록에 등록한다. 테스트 Worker의 저장소만 대상으로 한다.

## 정확도와 검증 범위

고정 코스는 지도에서 도착 검사를 통과한 기록과 사진 물체 판정을 함께 사용한다. 독립 사진 모듈은 GPS와 관계없이 이미지 인식을 시험한다. 사진 단계에서는 현재 GPS 정확도를 다시 검사하지 않는다. 기존 사진 단계의 방은 지도 전원 도착 사실로 기록을 복원한다. 제출 사진 원본은 게임 서버에 저장하지 않고 판정 결과와 기준 ID만 보관한다.

독립 모듈 방의 팀장은 사진 단계에서 물체 이름과 기준 사진을 함께 등록한다. 기준 원본은 방의 비공개 SQLite에 보관하며 인증된 참가자만 조회한다. 같은 기준은 팀 전체에 적용되고, 교체하면 진행 중인 판정을 취소한다. 다른 촬영 대상을 설정하면 이전 팀 기준을 해제한다. 방 초기화는 팀 기준을 삭제하고 기본 물병 기준으로 돌아간다.

기본 기준 등록은 관리자 인증 POST /api/photo-references/:id를 사용한다. 동일 ID와 같은 내용의 재등록은 기존 기록을 유지한다. 다른 내용은 새로운 ID로 등록하고 public/test-track.json의 referenceId를 갱신한다. 기준 사진과 비밀값은 Git 및 공개 assets에 저장하지 않는다.

NPC는 지원 Android의 WebXR과 iPhone Safari의 8th Wall 공간 추적 AR을 제공한다. 정령 시작 버튼을 누르면 현재 기기에 맞는 엔진을 선택하고 지원하지 않거나 실행에 실패하면 2D 정령으로 전환한다. 사용자는 카메라 2D를 직접 선택할 수도 있다. 정령 생성하기를 누르면 카메라 앞 약 1m에 정령이 자동 생성된다. WebAR 추적 초기화 중에는 카메라 앞에 표시하고 준비되면 공간에 고정한다. 정령을 직접 터치하면 이야기가 열린다. 공간 NPC는 각 기기에 따로 배치한다. [정령 정책 SSOT](../game/docs/261008_2228_정령_AR와_2D_정책_SSOT.md)는 버전 2로 관리한다. 카메라 길 안내는 중간 지점과 정령 위치의 두 경유점을 차례로 안내한다. 지정 좌표를 사용하는 시안으로 실제 보행 경로 API나 지리적 공통 AR 앵커를 제공하지 않는다.

브라우저의 센서 에뮬레이션 및 AR 요청 모사와 실제 휴대폰 검증을 구분한다. 현장 GPS, 세로로 든 휴대폰의 나침반 방향과 WebXR 및 WebAR의 정령 생성과 공간 고정 및 터치는 현장 시험을 마친 뒤 운영에 연결한다.
